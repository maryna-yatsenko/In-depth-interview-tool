## 1. Токени фіолетової шкали — новий блок `body.admin { }`

Селектор: `body.admin` (новий блок, замінює однорядковий
`body.admin { background: var(--bg); }`).

Було:
```css

```

Стало:
```css
body.admin {
  background: var(--bg);
  --accent: #8b71ee;
  --accent-soft: #c7b8f9;
  --accent-tint: #f5f0ff;
  --accent-strong: #5a33b5;
  --heading: #5a33b5;
  --on-accent: #fff;
}
@media (prefers-color-scheme: dark) {
  body.admin {
    --accent: #8b71ee;
    --accent-soft: #5a33b5;
    --accent-tint: #3d2f66;
    --accent-strong: #c7b8f9;
    --heading: #c7b8f9;
    --on-accent: #141414;
  }
}
```

Обґрунтування: `color-tokens.md`, розділ «Де міняти» — точний блок токенів,
скопійований дослівно (значення не вигадувались). `:root` у `web/styles.css`
не чіпався — синя шкала там лишається для сторінки респондента.

## 2. Кнопка `.primary` в адмінці — заливка `--accent-strong`, не `--accent`

Селектор: новий override `body.admin .primary` (сама `.primary` в
`web/styles.css` не редагувалась — вона поза скоупом).

Було: `.primary` (styles.css) використовує `background: var(--accent)`
— у фіолетовій шкалі це дає лише 3.69:1 для білого тексту (`--on-accent`),
не проходить поріг 4.5:1 для суцільного тексту кнопки.

Стало (додано в admin.css):
```css
body.admin .primary { background: var(--accent-strong); }
```

Обґрунтування: `color-tokens.md`, «Практичний висновок» — «там, де зараз
у admin.css/styles.css використовується --accent для тексту або тла кнопки
з білим текстом — підставляти #5A33B5». Значення `--on-accent` (#fff світла
тема / #141414 темна), задане в блоці 1, порахованo саме під пару з
`--accent-strong` (8.16:1 світла / 10.5:1 темна), а не з базовим `--accent`
— це підтверджує, що заливка primary-кнопки має йти через `--accent-strong`.

## 6. Бейдж інцидентів — заливка замість лише бордера

Селектор: `.run .pill.warn`

Було: `color: var(--danger); border-color: var(--danger);`
Стало:
```css
.run .pill.warn {
  color: var(--danger); border-color: var(--danger);
  background: color-mix(in srgb, var(--danger) 15%, var(--surface));
}
```

Обґрунтування: `hierarchy-patterns.md`, патерн 4 («Бейджі/пігулки для
статусу — кольорове тло, не тільки бордер») — `.pill.warn` явно названий:
«тільки міняє колір бордера й тексту на danger... варто дати заповнене
тло... і насичений текст того ж кольору (не приглушений сірий)». Точного
hex для «приглушеного danger-тла» в `color-tokens.md` немає (той файл
описує лише фіолетову шкалу) — замість вигадування нового hex-кольору тло
виведено як похідне від уже перевіреного семантичного токена `--danger`
через `color-mix()`, що одразу коректно працює і в світлій, і в темній
темі без окремих hex-констант на кожен режим. Текст лишається насиченим
`--danger` (не сірий) — так, як просить референс.

Базовий `.run .pill` (без `.warn`, лічильник реплік) не чіпався: це не
семантичний статус (Active/Approved/…), а нейтральний лічильник — референс
явно застерігає «не вигадувати нову кольорову мову для статусів», тому
вигадувати йому окремий заливний колір теж не варто.

  колір інший (danger, не accent) і в `color-tokens.md` для нього так само

  зміна тла великої картки (не малої пігулки) — помітніша, ризикованіша
  правка. Залишено без змін цього разу; якщо піде далі — той самий прийом

  прийом в майбутньому проході, якщо буде explicit рішення для

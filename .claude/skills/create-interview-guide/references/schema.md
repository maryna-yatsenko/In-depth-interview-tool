# Точна схема space.json і guides/*.json

Джерело істини — `app/config/space.py` (`load_space`/`load_guide`) і
`app/interview/phases.py` (`Plan.script()`/`Plan.sections()`). Якщо цей
документ і код колись розійдуться — вір коду й онови документ.

## space.json

Завантажується `load_space()`. Обовʼязкові поля позначені **обовʼязково**.

| Поле | Тип | За замовчуванням | Опис |
|---|---|---|---|
| `key` | string | **обовʼязково** | Ідентифікатор простору. |
| `title` | string | **обовʼязково** | Внутрішня назва. Показується як `<title>` сторінки й H1, **якщо** `branding.page_title` не задано. |
| `languages` | list[string] | **обовʼязково**, непорожній | Перша мова — основна (`primary_language`). |
| `persona.self_intro` | string | **обовʼязково** | Речення, яким інтервʼюер відкриває розмову; підклеюється перед текстом `opening` на першому питанні. |
| `persona.address` | string | `"ви"` | `"ви"` або `"ти"`. |
| `persona.tone` | string | `"нейтральний, стриманий"` | Тон інтервʼюера — довідково, не впливає на код. |
| `domain_vocabulary` | list[string] | `[]` | Довідкова лексика теми. |
| `branding.page_title` | string | — | Якщо задано — саме це йде в H1/заголовок вкладки замість `title`. |
| `branding.accent` | string (hex) | — | Колір `--accent` CSS-змінної на клієнті. |
| `report_sections` | list[string] | `[]` | Розділи майбутнього звіту дослідника — довідково. |
| `providers.llm` | object | `{}` | Наприклад `{"provider": "mlx", "model": "..."}`. |
| `providers.stt` | object | `{}` | Наприклад `{"provider": "browser"}`. **Обовʼязково задати** (не `none`/відсутній), якщо `interface.mode == "voice"` — інакше `load_space` кидає `ConfigError`. |
| `providers.tts` | object | `{}` | Наприклад `{"provider": "espnet", "voice": "...", "stress": "dictionary"}`. |
| `repertoire` | `"free"` \| `"bank"` | `"free"` | `"bank"` — інтервʼюер обирає з банку записаних людським голосом реплік. |
| `draft` | bool | `false` | `true` → простір-заготовка, реальне інтервʼю не стартує. |

### `privacy` (усе під ключем `privacy`)

| Поле | Тип | За замовчуванням | Опис |
|---|---|---|---|
| `never_ask_about` | list[string] | `[]` | Теми, яких інтервʼюер не торкається. **Гейт**: якщо `deidentify: true`, цей список не може бути порожнім — інакше `ConfigError`. |
| `deidentify` | bool | `false` | Увімкнути маскування персональних даних у транскрипті. |
| `consent_text` | string | `""` | Текст на екрані згоди. Підтримує `\n\n` як розрив абзацу (CSS `.consent` має `white-space: pre-wrap`). |
| `patterns` | list[{`name`, `pattern`}] | `[]` | Власні regex-шаблони маскування (наприклад, формат номера справи). Кожен `pattern` мусить компілюватись як Python `re` — інакше `ConfigError` одразу при завантаженні. |
| `use_builtin_patterns` | bool | `true` | `false` без власних `patterns` при `deidentify: true` → `ConfigError` (маскування нічого не робило б). |

### `interface` (усе під ключем `interface`)

| Поле | Тип | За замовчуванням | Опис |
|---|---|---|---|
| `mode` | `"voice"` \| `"text"` | `"text"` | `"voice"` — без поля ручного вводу взагалі, лише диктування; текстовий аварійний резерв зʼявляється сам, коли в браузері немає розпізнавання мовлення — його не треба увімкнути окремо. |
| `autoplay` | bool | `false` | Питання озвучується автоматично, щойно зʼявилось. |
| `record_voice` | bool | `false` | Дозволяє записувати сирий звук відповіді (не лише розпізнаний текст). Вмикає на екрані згоди галочку, без якої кнопка «Почати інтервʼю» лишається `disabled`. |
| `expected_words` | int ≥ 1 | `15` | Скільки слів вважається «розгорнутою» відповіддю — на це орієнтується смуга обсягу над мікрофоном і підсумкова кольорова позначка (зелена/жовтогаряча/нейтральна). У `spaces/travel` стоїть `40`. |
| `min_words_to_credit` | int | `3` | Нижня межа: коротше — рушій не рахує це відповіддю взагалі. |

**Гейт**: `mode == "voice"` вимагає, щоб `providers.stt.provider` було задане й не `None`/`"none"` — інакше простір не завантажиться (голосовий режим без розпізнавання дав би екран, на якому нічого не можна сказати).

## guides/<name>.json

Завантажується `load_guide()`. Простір читає з `guides/` **перший файл за
алфавітом**, якщо конкретний `guide_key` не передано явно — тримай один файл
на просту тему.

| Поле | Тип | За замовчуванням | Опис |
|---|---|---|---|
| `key` | string | **обовʼязково** | Ідентифікатор гайда. |
| `goal` | string | **обовʼязково** | Що дослідник хоче зʼясувати цим гайдом — довідково для людей, не для коду. |
| `topics` | list[Topic] | **обовʼязково**, непорожній | Див. нижче. |
| `opening` | string | `""` | Перше питання. На нього підклеюється `persona.self_intro` спереду. |
| `opening_expects` | list[string] | `[]` | Чекліст під `opening`. |
| `narrative` | object \| відсутнє | — | Якщо блок присутній, `narrative.prompt` **обовʼязковий** (інакше `ConfigError`) — фаза розповіді без запиту на розповідь не має сенсу. |
| `narrative.prompt` | string | — | Питання-запрошення розповісти вільно. |
| `narrative.turns` | int | `0` | Інформаційна межа — легасі вільного режиму, у сценарному не використовується напряму. |
| `narrative.holds` | list[string] | `[]` | Короткі реплики типу «Ага.», «І що далі?» — **лише для вільного режиму** (`self.script` порожній); сценарний режим їх не показує. |
| `max_turns` | int | `40` | Легасі-межа вільного режиму. |
| `closing_questions` | list[string \| {`text`, `expects`}] | `[]` | Підсумкові питання. Рядок або обʼєкт із власним чеклістом. |
| `closing` | string | `""` | Прощальна репліка, яку каже `Session.finish()`. |
| `deepening` | list[string] | `[]` | Легасі вільного режиму — фрази заглиблення при узагальненні. Не діють у сценарному режимі. |
| `generalization_markers` | list[string] | `[]` | Легасі вільного режиму — лексичні маркери узагальнення («завжди», «зазвичай»). Не діють у сценарному режимі. |

### Topic (елемент `topics`)

| Поле | Тип | За замовчуванням | Опис |
|---|---|---|---|
| `id` | string | **обовʼязково**, унікальний | Формує ідентифікатори питань `<id>/1` (`ask_if_missed`) і `<id>/2` (`ask_for_detail`), і `question_id` у транскрипті. |
| `title` | string | **обовʼязково** | Дослідницька назва теми — те, що бачить дослідник у транскрипті й звітах. |
| `goal` | string | `""` | Довідково, що ця тема хоче зʼясувати. |
| `ask_if_missed` | string | `""` | Питання рівня 1 — якщо тему взагалі не згадали. |
| `ask_for_detail` | string | `""` | Питання рівня 2 — довести до конкретики. |
| `must_learn` | list[string \| {`text`, `needs_detail`, `min_words`}] | `[]` | Чекліст «про що варто сказати» на обох питаннях цієї теми. Рядок береться як є; обʼєкт — використовується `text`, а `needs_detail`/`min_words` **ігноруються сценарним режимом** (це легасі механізму оцінки вільного режиму). |
| `max_probes` | int | `4` | Легасі вільного режиму. |
| `shown_as` | string | `""` (тоді береться `title`) | Респондентська назва теми — коротка, звичайною мовою; показується в кроці прогресу нагорі (на телефоні обрізається трьома крапками, тримай короткою). |

### closing_questions — елемент може бути

- просто рядок — питання без власного чекліста;
- обʼєкт `{"text": "...", "expects": ["..."]}` — питання з переліком очікуваного під ним.

## Як з цього будується сценарій (`Plan.script()`)

Плоский, людино-керований список питань — саме в цьому порядку, без винятків:

1. `opening` (якщо непорожній) → `id: "opening"`, `expects: opening_expects`.
2. `narrative.prompt` (якщо є блок `narrative`) → `id: "narrative"`,
   `expects:` **лейбли всіх тем** (`shown_as` або `title`) — респондент бачить
   мапу того, про що піде розмова далі.
3. Для кожної теми **по порядку списку** `topics`:
   `ask_if_missed` (якщо непорожній) → `id: "<topic.id>/1"`,
   `expects: must_learn`; потім `ask_for_detail` (якщо непорожній) →
   `id: "<topic.id>/2"`, `expects: must_learn` (той самий перелік на обох
   рівнях теми).
4. Для кожного `closing_questions[i]` → `id: "closing/<i>"`,
   `expects: closing_expects[i]` (або `[]`).

## Розділи прогресу (`Plan.sections()`)

Показуються нагорі лише ті, для яких у гайді є відповідний контент:

| Розділ | Зʼявляється, якщо |
|---|---|
| «Початок» | завжди (навіть якщо `opening` порожній — але тоді питань там немає) |
| «Розповідь» | `narrative` блок присутній (є `narrative.prompt`) |
| «Уточнення» | `topics` непорожній |
| «Підсумок» | `closing_questions` непорожній |

Кожен розділ на клієнті показує `total`/`answered` — реальну кількість питань
у ньому, а не позицію курсора.

## Типові помилки `ConfigError` і що вони означають

| Повідомлення (скорочено) | Причина |
|---|---|
| «не заповнені обовʼязкові поля: …» | Пропущено `key`/`title`/`languages`/`persona` у space.json, або `key`/`goal`/`topics` у гайді, або `id`/`title` в темі. |
| «languages має бути непорожнім списком» | `languages` порожній або не список. |
| «deidentify=true, … never_ask_about порожній» | Додай хоч один пункт у `privacy.never_ask_about`. |
| «deidentify=true, вбудовані шаблони вимкнені, власних немає» | Або залиш `use_builtin_patterns: true`, або додай `privacy.patterns`. |
| «шаблон '...' не компілюється» | Regex у `privacy.patterns[].pattern` синтаксично невірний. |
| «interface.mode: '...' невідомий» | Тільки `"voice"` або `"text"`. |
| «interface.mode='voice', але провайдер stt не заданий» | Додай `providers.stt.provider` (наприклад `"browser"`). |
| «interface.expected_words: очікується ціле число більше нуля» | `expected_words` мусить бути `int >= 1`. |
| «topics має бути непорожнім списком» | Гайд без жодної теми. |
| «Дубльований id теми: …» | Два `topics[].id` однакові — id мусять бути унікальні в межах гайда. |
| «narrative: є блок, але немає `prompt`» | Прибери порожній блок `narrative` цілком, якщо він не потрібен, замість лишати його без `prompt`. |
| «closing_questions: питання без тексту» | Обʼєкт у `closing_questions` без `text`. |
| «Пункт must_learn без тексту» | Обʼєкт у `must_learn` без `text`/`learn`. |
| «У просторі '...' немає теки guides/» | Створи `spaces/<key>/guides/` і поклади туди хоч один `*.json`. |

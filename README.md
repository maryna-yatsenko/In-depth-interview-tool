# Interview tool

Продукт для проведення автоматизованих голосових якісних інтервʼю: дослідник
створює й налаштовує дослідження в панелі керування, респондент проходить
інтервʼю голосом у браузері, а на виході — транскрипт, готовий до аналізу.
Жодне дослідження не зашите в код — усе, що є в панелі, це конфіг, а не текст
програми.

Контекст, план і рішення проєкту: **[`docs/ai/`](docs/ai/)** (читати перед
роботою над кодом).

⛔ Реальне інтервʼю неможливе без LLM-ключа: двигун не вмикається без нього.

## Що це за продукт

Два екрани одного інструменту:

- **Панель дослідника** (`/admin`) — робоче місце, де дослідження створюються,
  редагуються й керуються. Основний інтерфейс продукту.
- **Сторінка респондента** (`/`) — те, що бачить людина, яку інтерв'юють:
  голосом або текстом, за сценарієм, який дослідник задав у панелі.

Один сервер може одночасно обслуговувати кілька досліджень — кожне зі своїм
робочим посиланням для респондентів (`?space=<ключ>`), яке панель копіює
однією кнопкою.

## Панель дослідника

- **Дослідження** — створюються з панелі («+ нове»), кожне живе своєю чернеткою,
  доки дослідник не позначить його готовим: респондент не потрапить у
  недописаний простір.
- **Гайд** — питання, чекліст «про що варто почути» під кожним, порядок
  питань перетягуванням, розмежування формулювання «для себе» і того, що
  бачить респондент.
- **Вигляд для респондента** — режим інтерфейсу (голос без поля введення чи
  текст), акцентний колір, мови.
- **Голос питань** — дослідник може начитати питання власним голосом
  (мікрофон біля картки питання) або, у режимі банку реплік, начитати весь
  набір формулювань наперед — респондент чує живий голос, не синтез.
- **Результати** — список проведених інтервʼю з транскриптом, записами
  голосу респондента (за згодою) й оцінкою досвіду проходження.
- **Кошик** — видалені дослідження не зникають одразу: перенесення в кошик,
  відновлення, остаточне видалення — окремими кроками.
- Світла й темна тема, копіювання прямого посилання на форму респондента для
  конкретного дослідження.

Дослідження, які вже лежать у `spaces/` (наприклад приклад і референсний
простір), — це готові приклади того, що можна створити цим інструментом, а
не частина самого продукту. Свій простір можна почати з нуля прямо в панелі.

## Вимоги

- Python 3.9+ і `git` — більше нічого не потрібно ставити заздалегідь.
- Локальна модель (MLX, `gemma-3-4b-it-4bit`) працює лише на Apple Silicon і
  опціональна: без неї інструмент так само працює на заглушці (`--llm mock`)
  або на Claude API (`--llm anthropic`) — на будь-якій ОС.

## Запуск

Двічі клікнути `local/start.command` у Finder — або в терміналі (з кореня
проєкту, працює й не на macOS):

```bash
./local/start.command
```

Перший запуск сам створює `.venv` і ставить залежності з `requirements.txt` —
нічого встановлювати вручну не треба. Сервер піднімається **незалежно від
будь-якої сесії Claude** (nohup, pid у `.server.pid`, логи в
`local/.server.log`) і сам відкриває сторінку (на macOS/Linux; деінде —
просто відкрий надруковану адресу вручну). Зупинити — `./local/stop.command`.
Повторний запуск не дублює процес.

- Респондент: `http://127.0.0.1:8770`
- Дослідник: `http://127.0.0.1:8770/admin`

Мікрофон працює тільки на `localhost` або https — це обмеження браузера, не
наше.

Провайдер моделі береться **з конфігу простору**; змінна лише перекриває:

```bash
LLM=mock ./local/start.command          # заглушка, без витрат і без моделі
LLM=anthropic ./local/start.command     # Claude API, якщо є ключ
./local/start.command spaces/моя-тема   # інший простір за замовчуванням
```

Панель дослідника вмикає прапорець `--admin`, який `local/start.command`
ставить сам. Без нього панелі **не існує** взагалі, а не «існує, але
закрита» — публічний запуск не може випадково її відкрити.

Запуск вручну, якщо потрібен контроль:

```bash
python3 local/serve.py --space spaces/example --llm mock --admin
```

Справжнє інтервʼю потребує ключа у файлі `.env` у корені (він у
`.gitignore`):

```bash
echo 'ANTHROPIC_API_KEY=ваш-ключ' > .env
.venv/bin/python local/cli.py --space spaces/example --llm anthropic
```

Кнопка «Скопіювати посилання» в панелі дослідника веде на форму респондента за
адресою `RESPONDENT_URL`. На Vercel вона вже задана; локально додайте її в `.env`
(інакше посилання буде на `127.0.0.1`, яке ніхто, крім вас, не відкриє):

```bash
echo 'RESPONDENT_URL=https://ваш-проєкт.vercel.app' >> .env
```

Термінальний канал без ключа й без витрат — перевіряє механіку:

```bash
python3 local/cli.py --space spaces/example --llm mock --auto --no-save
```

Тести (працюють і на системному Python — ядро без залежностей):

```bash
python3 -m unittest discover -s tests
```

## Як це влаштовано

| Де | Що |
|---|---|
| `app/interview/session.py`, `phases.py` | ядро: сценарій/банк веде розмову, коли модель відповідає, а коли ходом керує сам код |
| `app/config/space.py` | конфіг простору — уся доменна специфіка дослідження |
| `app/providers/` | єдине місце, де інструмент знає про LLM-вендорів |
| `app/api/server.py` | HTTP-шар респондента: сесія, кроки сценарію, статичні файли |
| `app/api/admin.py` | HTTP-шар панелі дослідника |
| `web/` | обидва фронтенди — `index.html`/`app.js` (респондент), `admin.html`/`admin.js` (панель) |
| `spaces/` | дослідження: `space.json` + `guides/*.json` на кожне |

## Усе безкоштовно і локально

| Частина | Чим | Ціна |
|---|---|---|
| Мозок інтервʼюера | локальна модель через MLX (типово `gemma-3-4b-it-4bit`) | 0 |
| Голос питання | живий запис дослідника з панелі, за бажанням | 0 |
| Розпізнавання відповіді | Web Speech API браузера | 0 |

Нічого не покидає машину, окрім розпізнавання мовлення — воно в Chrome
рахується не на пристрої, а на серверах вендора браузера: для особистого
контуру прийнятно, для корпоративного потрібен серверний STT.

## Приватність і деідентифікація

Дослідження може вмикати автоматичне маскування персональних даних
(`privacy.deidentify` у конфігу простору) — пошта, посилання, телефон,
довгі числові послідовності. Маскування стоїть на вході, до того, як текст
іде до моделі, і кожне спрацювання видно в транскрипті. Дослідник може
додати власні формати (`назва | регулярка | замінник`) просто в панелі.

Запис голосу респондента вимикається за замовчуванням і вмикається лише
за двох умов одночасно: дослідження це дозволяє, і респондент окремо
погодився на екрані згоди.

## Порада для macOS: проєкт у ~/Desktop під iCloud

Це не крок налаштування — на будь-якій іншій машині чи ОС `.venv/` і
`local/data/` просто будуть звичайними локальними теками, і цей розділ
можна пропустити.

Стосується лише випадку, коли сам проєкт лежить у `~/Desktop`, а ця тека
синхронізується через iCloud Drive (типове macOS-налаштування). Тоді
`.venv/` (сотні МБ) і `local/data/` (первинні дані досліджень) там — поганий
дім: обидва мають синхронізуватись через iCloud без потреби. Рішення на
такий випадок: винести обидві теки, наприклад у `~/.interview-tool-data/`
(поза iCloud), а в проєкті на їхньому місці зробити символьні посилання
(`.venv` → …/venv, `local/data` → …/data) — `git status` їх не бачить, обидва
шляхи вже в `.gitignore`.

Окрема від цього річ — TCC: деякі процеси (наприклад лаунчер превʼю,
`.claude/launch.json`) не можуть відкривати файли під Desktop без явного
дозволу «Files and Folders» у Налаштування → Конфіденційність і безпека,
незалежно від того, де лежать `.venv`/`local/data`. Це дозвіл самої macOS
для конкретного застосунку, тут його видати не можна.
